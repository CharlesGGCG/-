# 维护阶段归纳

> 把 `本地` 分支（在 v0.8.9 之上）的维护提交，按演进思路归纳为四个阶段。
> 提交哈希可用 `git log` 直接定位；除注明上游外，其余均为本仓自己的维护提交。
> 本文档与上游 [Mieksido/surfcore](https://github.com/Mieksido/surfcore) 的 CHANGELOG 无关，只记录本仓的分支演进。

## 阶段一 · 直接引用，论证现有方案效果

- **基线**：`0ce8580`（tag `v0.8.9`，上游 Mieksido/surfcore 原样，未改一行）
- **做了什么**：不写自己的代码，按上游 README 原样部署跑通，验证「现有方案」本身能落地——QQ 收发、人格、情绪、日记、QQ 空间、B站、本地语音全部可用。
- **结论**：原方案骨架成立。暴露出的两个缺口——① 对**视频 / 语言等多媒体内容**的理解不够；② 表达**不够像人**——分别引出阶段二、阶段三。

## 阶段二 · 增加功能：帮她理解视频与语言内容

- **时间**：2026-11-07 前后（`4845ddb`）
- **做了什么**：一批能力补丁——
  - 语言：QQ 语音转写（`qq_get_voice_text`）
  - 视频：B站 分片下载绕开 567 风控（`qq_download_bili_video`）+ `video_storyboard` 看画面
  - 图片 / 表情：发图（`qq_send_image`）+ 大肥鱼表情包链路（sticker_search → sticker_send → 发图）
  - 其它：她的房间（`her-room` MCP）、QQ 空间（`room_publish_qzone`）、下线仪式
- **目的**：补上「听懂语言、看懂视频」的能力，让模型能基于多媒体内容交流。
- **关键提交**：`4845ddb` feat: 小鲸鱼维护批次——语音转写/分片下视频/发图/她的房间/QQ空间/表情包/下线仪式

## 阶段三 · 修改提示词：从「命令式」到「睡醒后的第一人称回忆」

- **时间**：2026-11-08（`9a5ed7f` → `fb5a2d2`）
- **背景**：用了一段时间后发现「不够人味」。
- **做了什么**：以「模拟一个真人睡醒后、自然而然用第一人称回忆自己记忆」为目标改提示词——
  1. 唤醒提示词改「醒来叙事」版：把内容织成刚醒独白（我是谁 / 刚才 / 主人 / 我还记着 / 现在），规矩用「乖女儿」口吻（`9a5ed7f`）
  2. 人格卡整体第二人称改第一人称（你是 → 我是）（`24f8da4`）
  3. 重建「女儿版」人格，并加「没必要每条强调是女儿」防过度黏（`f13bb8c`）
  4. 身份底座剥掉「角色卡：/——/DeepSeek 」前缀 → 变成「我是小鲸鱼」（`fb5a2d2`）
- **目的**：让唤醒提示词像「人刚醒」，而不是满屏【命令式】。
- **关键提交**：`9a5ed7f`、`24f8da4`、`f13bb8c`、`fb5a2d2`

## 阶段四 · 细分提示词 + 多媒态喂入 + 逐步减少提示词 + 找记忆方案（进行中）

- **时间**：2026-11-08 起（当前）
- **做了什么**：开始转向——
  1. 跨会话共享记忆：`qq_shared_memory` 工具 + `state/shared-memory.json`，每次唤醒注入「关于主人」的事实（`be02457`）
  2. 提示词细分拆解，方向调整为「**把多媒态信息喂给她 → 观察效果 → 逐步减少提示词 → 寻找能充当记忆的方案**」
- **目的**：不再靠越来越长的提示词堆人味，而是让「记忆 / 多媒态信息」成为她认知的来源，提示词逐步瘦身。
- **关键提交**：`be02457` feat: 跨会话共享记忆（关于主人）
- **待验证**：提示词瘦身后行为是否退化；记忆方案（固化 / 卡片 / 多媒态）选哪条。
