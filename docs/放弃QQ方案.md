# 放弃 QQ 方案

> 结论先行：**鲸鱼的本体在本地，QQ 只是她的一条腿。放弃 QQ ≠ 放弃她，而是把「她跟人说话的门」从腾讯手里搬回自己的地盘。**

## 一、为什么放弃 QQ

**唯一原因：封控风险不可控。**

QQ 收发依赖 SnowLuma 走 OneBot 非官方协议，腾讯随时可能封号；一旦封号，「她活在群里」这条命就没了，且没有申诉保证。

拆开看，QQ 其实只提供两件事：

1. **主人随时找她说话**；
2. **她跟更多人（群友）交流**。

这两件事**都有零封控风险的替代**，所以 QQ 从「主通道」降级成「可选通道」。

## 二、替代方案：本地 + B站

| QQ 提供的 | 替代 | 风险 |
|---|---|---|
| 主人和她聊天 | 本地桌宠 / 邀请 Web / DSH Web / 语音 | 零（全在自己 PC） |
| 和粉丝公开交流 | B站 动态 + 评论 + 直播弹幕 | 低（B站 自有风控，与腾讯无关） |
| 和几个朋友半私密聊 | 邀请制 Web（whaleweb + 隧道） | 零（自己服务器 + 邀请码） |

## 三、核心逻辑（一句话）

她的「人」——人格、记忆、情绪、语音、B站——**全都住在本地 DSH 里**，QQ 只是众多入口之一。把入口从 QQ 换成桌宠 / 网页 / B站，她照样是她，且不再看腾讯脸色。

一句话概括这次转向：

> **「给她一个不靠腾讯也能活下去的家」** —— 门在自己手里，通道可插拔，脑子和记忆原地不动。

## 四、落地状态

**已完成：**

- 本地桌宠（surfcore 内置 pet-api + surfpet 壳，5 套皮肤 + 文本/语音对话）
- 邀请制 Web `whaleweb`（Cloudflare 隧道 + 邀请码，`https://whale.whalemory.com`）
- B站 公开交流（动态 / 评论 / 直播弹幕，早已在跑）

**保留（与 QQ 无关）：** B站、人格卡、记忆、语音、桌宠、共享记忆。

**可停用：** QQ 桥接（SnowLuma）、QQ 白名单 / 群配置。

## 五、邀请制 Web（whaleweb）怎么接

```
朋友浏览器 → https://whale.whalemory.com（带邀请码）
  → Cloudflare 隧道（cloudflared，开机自启）
  → 本地 whaleweb 服务（8787，邀请门 + 转发）
  → 桌宠 pet-api（DSH 里的 surfcore）
  → 小鲸鱼（人格 + 记忆，与 B站 同一颗脑）
```

代码在 `whaleweb/`，一个 Node 文件（`server.mjs`）+ 一个前端页（`public/index.html`），零依赖。邀请码、端口在 `config.json`（不入库，模板见 `config.example.json`）。
